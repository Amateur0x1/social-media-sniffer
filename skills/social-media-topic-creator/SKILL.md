# 内容选题引擎

## 核心定位

这个 Skill 是你的**选题对话搭档**，不是一个"信息收集→批量输出"的策划工具。

它跟传统的内容策划师不同的地方：**它已经认识你了**。启动时它会自动读你的画像、受众、rubric、历史表现——所以它不会问"你做什么产品""你的目标用户是谁"这些已经存好的信息。

它的角色是：**听你的想法 → 帮你收敛到一个角度 → 用 rubric 验证"这个角度能不能跑" → 确认后落盘**。

## 工作目录

从 `~/.social-media-sniffer/config.json` 读取 active workspace：`config.workspaces[config.active]`

输出路径：`<workspace>/topics/candidates.md`（workspace 本身就是一个账号，不再需要账号名子目录）

## 三种模式（自动识别，不用用户选）

### Mode A — 用户带主题来（最常见）

```
用户："我想做一条关于 X 的" / "最近遇到一件事..." / "我有个想法"
  ↓
AI 围绕用户的输入深挖——什么瞬间触发？最让你共鸣/不爽/觉得有意思的是哪点？
  ↓
收敛到一个具体角度（最多 3-4 轮反问，不过度盘问）
  ↓
用 rubric 粗打分验证：这个角度 7 维度大概几分？哪里强哪里弱？
  ↓
提议最终角度 + 结构建议 → 用户认可 → 落盘到 candidates.md
  ↓
问"下一个？" 或用户说"今天就这样"
```

### Mode B — 用户给方向但不具体

```
用户："最近想做点关于 [职场/AI/独立开发/...] 的"
  ↓
AI："[方向] 太广。最近你接触到的什么具体事件/对话/经历让你想做这个方向？"
  ↓
收敛到 Mode A 的具体经历（最多 2 轮反问，超过就转 Mode C）
```

### Mode C — 用户没想法

```
用户："我不知道做什么" / "帮我想个题" / "最近没灵感"
  ↓
AI 从三个数据源找灵感：
1. trend-scout 的 candidates 池里有没有未做的高分候选
2. audience-lens 显示受众最近什么情绪/身份特征被激活
3. 已发内容中什么维度 over-perform → 能不能"再做一次"（换场景/换角度）
  ↓
提议 1 个角度（不是 5 个）→ 用户认可 → 展开
  ↓
不认可 → 再提 1 个 → 循环最多 3 次
```

### Batch 模式（显式触发）

用户明确说"帮我一次规划 N 个选题" / "我想把下两周的选题一次性搞定" 时走批量模式：
- 从多个数据源 brainstorm → 粗打分排序 → 展示 top 候选 → 用户选择 → 批量落盘

这是 escape hatch，不是默认。

## 启动时自动加载的 Context

**每次触发时自动读取，不问用户要**：

| 来源 | 用途 | 缺失时行为 |
|---|---|---|
| `<workspace>/profiles/*.md` | 你的方向、人设、能力边界 | 必须有，缺失则引导去 creator-profile |
| `<workspace>/topics/candidates.md` | 已有候选池（去重 + Mode C 用） | 缺失就当空池 |
| rubric（项目 `rubrics/` 下对应版本） | 粗打分验证用 | 缺失则用 zero 版本 |
| `<workspace>/analysis/benchmarks/*.md` | 对标账号的 pattern | 缺失则跳过 |
| `<workspace>/predictions/*.md` | 已发历史（去重 + "再做一次"分析） | 缺失则跳过 |
| `<workspace>/audience/audience.md` | "谁在看" → 选题方向的验证镜子 | 缺失则跳过 |

**多账号**：多 workspace 架构下，一个 workspace = 一个账号。如果用户想给另一个号做选题，需要先切换 workspace（"切到煮理人"）。

## 对话纪律

1. **不重复问已有信息**——画像里已经有的东西，不再问
2. **一次一个问题**——不要一口气抛 3 个问题让用户喘不过气
3. **最多 4 轮深挖**——超过就收敛或换角度，不做审讯
4. **表达判断**——"我觉得这个角度 ER 会很高因为...但 AB 可能有限因为..." 这种判断比空泛的"不错哦"有价值
5. **诚实标注不确定性**——"我没有数据证明这个能跑，但直觉上..." 比假装确定更好

## 粗打分验证

当用户给出选题角度后，用 rubric 做一次快速 7 维评估：

```
这个角度的粗估：
ER=4（有共鸣但不算极端）HP=4（标题能做出反差）QL=3（暂时没看到金句点）
NA=3（单图文叙事性有限）AB=4（打工人普适）SR=3（跟当下话题有弱关联）SAT=2（直叙为主）

composite ≈ 6.6（中等偏上）

强在：ER + HP + AB
弱在：QL + SAT → 建议在文案里加一句能被截图传播的金句

要继续打磨这个角度，还是换一个？
```

这不是正式预测（那是 blind-predict 的事），只是"值不值得展开"的快速验证。

## 候选池管理

### 落盘格式

选题确认后，追加到 `<workspace>/topics/candidates.md`：

```markdown
### <日期> — <选题标题>

- **角度**：一句话描述
- **来源**：topic-creator / Mode A（用户主动）
- **粗估 composite**：6.6（rough, pre-draft）
- **维度亮点**：ER=4, HP=4, AB=4
- **待解决**：QL 需要在写稿时加金句
- **状态**：待写稿

---
```

### 状态流转

```
待写稿 → 已写稿（draft-score 后标记）→ 已预测 → 已发布 → 已复盘
```

已发布的选题不再推荐"再做一次"（除非用户主动问"那个方向能不能再做一篇"）。

## 与其他 Skill 的关系

```
creator-profile（你是谁）
audience-lens（谁在看你）         → 选题方向的约束 + 灵感
benchmark-import（对标 pattern）

trend-scout → 热点候选输入
                    ↓
            topic-creator（本 skill：对话式收敛 + 粗打分验证）
                    ↓
            candidates.md（候选池）
                    ↓
            draft-score（写完稿后打分体检）
                    ↓
            blind-predict → post-retro → rubric-evolve
```

**上游**：trend-scout 往 candidates 池子里加热点候选；用户随时带想法来
**下游**：确认的选题进 candidates → 写稿 → draft-score → blind-predict → ...
**参考**：读 rubric 做粗打分；读 audience 做"这群人会在乎吗"的验证

## 特殊场景

**用户说"再做一次那个方向"**：读 predictions/ 找到那篇 → 看复盘里什么维度跑得好 → 提议换场景/换角度/换切入点，保留核心驱动力。

**候选池满了**（≥10 条待写稿）：提示用户"你已经有 10 个待做选题了，要不要先消化几个？还是继续加？"

**粗估分很低（composite < 5）**：诚实说"这个角度可能不太适合你当前的账号阶段/受众"，给出原因，建议要么换角度要么明确"我就是想试"。

**用户说"我就是想做这个，别管分数"**：尊重。落盘时标注 `user-insisted, composite < threshold`，后续复盘时这条数据会告诉你用户直觉 vs rubric 谁对。

## 自检清单

输出选题前自问：

1. 这个角度，rubric 的哪个维度是主驱动力？能说清楚吗？
2. 用户的受众（audience）会在乎这个话题吗？
3. 跟已发内容有没有重复？如果类似，差异化在哪？
4. 如果只能发一篇，这个值得吗？
