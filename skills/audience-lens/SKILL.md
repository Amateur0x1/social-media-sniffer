# audience-lens — 受众画像派生

## 这个 Skill 做什么

从你的 post-retro 复盘数据中（主要是评论内容），通过聚类分析派生出你的**真实受众画像**——他们是谁、为什么来看你、来找什么情绪、用什么语言说话。

## 跟 creator-profile 的区别

| | creator-profile | audience-lens |
|---|---|---|
| 回答 | "我是谁、我想做什么" | "谁真的在看我、他们为什么来" |
| 数据源 | 用户自述 + 发布数据指标 | 评论文本聚类 + 互动行为 |
| 建立时间 | 冷启动就能建 | 需要积累复盘数据（≥ 3 篇有评论的复盘） |
| 核心价值 | 定义方向 | 验证/修正方向 |

两个共存，不替代。audience-lens 最有价值的时刻是发现"你以为的受众 ≠ 你实际的受众"——这个 gap 本身就是战略信号。

## 工作目录

从 `~/.social-media-sniffer/config.json` 读取 active workspace：`config.workspaces[config.active]`

产出写入：`<workspace>/audience/audience.md`

## 数据来源

| 来源 | 信号类型 |
|---|---|
| 复盘段的 top 评论 | **主数据源**——评论文本 + 赞数 |
| 互动数据比率 | 薄信号——藏赞比高说明"实用型受众"，评赞比高说明"讨论型受众" |
| benchmark 评论（如有） | 冷启动 seed——"看对标的人 ≈ 你想要的人" |

## 前置条件

| 情况 | 行为 |
|---|---|
| 0 篇复盘 + 无 benchmark | 拒绝执行——"没有数据就没有画像，先发几篇跑完复盘再来" |
| 0 篇复盘 + 有 benchmark | 生成一份"未验证的种子画像"，全文标注"基于对标数据推测，未经你自己的评论验证" |
| 1-2 篇有评论的复盘 | 可以产出但置信度低，多数特征标"假设" |
| ≥ 3 篇有评论的复盘 | 正常产出，可做验证性结论 |

## 工作流程

### Phase 1: 收集数据

扫描 `<workspace>/predictions/` 下所有预测文件的 `## 复盘` 段：
- 提取 top 评论内容和赞数
- 提取互动数据（赞/藏/评/分享）
- 统计有评论的复盘篇数

### Phase 2: 评论聚类

按四个维度分析评论：

**1. 自我认同**——"我也是…"/"作为一个…"模式
- 什么身份标签反复出现？
- 例："大厂打工人""同文科转码""一人公司想做但没勇气"

**2. 情绪寄存**——他们来评论是为了什么情绪？
- 被验证（"说得太对了"）
- 宣泄（"我也好累"）
- 求助（"那该怎么办"）
- 抬杠（"我不同意，因为..."）
- 占比分布

**3. 反驳点**——哪些观点引来稳定反对
- 这是你内容的"边界"——反复被反对的点说明"你在推某些人的按钮"
- 边界可以是好事（有争议 = 有立场 = 有人设）

**4. 语言风格**——他们怎么说话
- 玩梗密度、真诚 vs 戏谑
- 有没有复制你的金句
- 有没有创造新梗

### Phase 3: 交叉检验

把 audience-lens 的发现跟 creator-profile 做对比：

```
creator-profile 说："我的目标受众是想转码的文科生"
audience-lens 发现："实际评论者 80% 是已在职的大厂人，想做副业/独立开发"

→ Gap signal: 你吸引的不是"还没转码的人"，而是"已经转完了但想更进一步的人"
```

这种 gap 不是错——它是战略信息。用户可以选择：调整方向适配真实受众，或者调整内容去吸引目标受众。

### Phase 4: 写入

产出格式：

```markdown
# 白日梦想猪 — 受众画像

**版本**: v1
**置信度**: 🟡 早期信号（基于 2 篇有评论的复盘）
**数据基础**: 2 篇复盘 / 15 条评论
**上次更新**: 2026-07-10

## 验证特征（有数据支撑）
- [特征] + 证据条数 + 出处

## 假设特征（待验证）
- [特征] + 为什么猜测 + 需要什么数据验证

## 反画像（不是你的受众）
- [描述] + 为什么排除

## 情绪地图
- 来找什么情绪的分布

## 语言特征
- 他们怎么说话

## creator-profile × audience-lens 交叉检验
- Gap 1: ...
- Gap 2: ...

---
版本历史：
- v1 — 基于 2 篇复盘 / 15 条评论，主要发现：...
```

## 关键规则

1. **数据派生，不手写**——画像必须从评论/行为聚类而来。用户想手动加 → 允许但标"user-asserted（未经数据验证）"
2. **验证特征需要 ≥ 3 条评论证据**——不够的降到"假设特征"
3. **不替代 creator-profile**——profile 是"你的自我定义"，audience-lens 是"数据的回音"
4. **覆盖式重建**——每次执行重写全文（audience 是活文档），只在版本历史 append 一行
5. **矛盾不调和**——profile 和 audience-lens 冲突时如实标出 gap，不强行编一个故事
6. **局限性诚实**——评论 ≠ 全部受众（沉默大多数不在数据里），明确标注

## 与其他 skill 的关系

- **上游**：post-retro 积累评论数据 → 触发 audience-lens 更新
- **下游**：topic-creator 选题时参考"我的受众在乎什么"；trend-scout 过滤热点时参考"这话题我的受众会不会关心"
- **互补**：creator-profile（我是谁）+ audience-lens（谁在看我）= 完整的内容战略视角
- **联动**：rubric-evolve 可以参考 audience-lens（"受众不在乎 NA → 可以降权"）
