# draft-score — 发前体检

## 这个 Skill 做什么

用 7 维度 rubric 给你写好的稿子打分，告诉你 composite 分数是多少、哪个维度强哪个维度弱。**不写任何文件、不做预测**——纯粹是一个"写完稿子快速体检"的动作。

你可以反复打分不同版本的稿子，确定一份之后再去 blind-predict 做正式预测。

## 为什么需要它

你的直觉告诉你"这条会火"，但可能是幻觉。draft-score 提供一个结构化的检查清单：
- HP 只有 2？→ 说明你的标题/封面/开头不够钩人
- QL 只有 1？→ 缺金句，读者看完不会截图传播
- ER 有 5 但 AB 只有 1？→ 情感很强但太小众，天花板低

这些诊断信息帮你在发布前有针对性地改稿，而不是发完了数据不好才事后归因。

## 工作目录

从 `~/.social-media-sniffer/config.json` 读取 active workspace：`config.workspaces[config.active]`

rubric 来源：`<项目根>/rubrics/xhs-image-text-zero.md`（或最新版本）

## 输入

| 必填 | 来源 |
|---|---|
| 稿子内容 | 用户提供路径或直接粘贴文本 |
| rubric 文件 | `rubrics/` 目录下当前生效的版本 |
| benchmark 锚点（可选） | `<workspace>/analysis/benchmarks/` 下的对标数据 |

## 工作流程

### Step 1: 读取稿子

用户提供稿子的方式：
- 给文件路径（如 HTML 卡片的 body-source 文本内容）
- 直接在对话里粘贴正文
- 指向已有的选题/草稿文件

### Step 2: 读取当前 rubric

从 `rubrics/` 目录找当前生效的 rubric 版本（初始是 `xhs-image-text-zero.md`）。
解析出：7 个维度定义 + 公式 + bucket 方案。

### Step 3: 逐维度打分

对每个维度给 0-5 整数分 + 一行理由（15-30 字）：

**打分原则**：
- 严格按 rubric 定义的 0-5 标准打
- 理由必须引用稿子里的具体内容（不能是"还行""不错"这种空话）
- 如果某个维度的稿子信息不足以判断（比如没看到封面设计），标注"信息不足，按文本内容估"

### Step 4: 算 composite

按当前公式计算综合分。

### Step 5: 输出

控制台输出格式：

```
📊 [稿子短标题] — 打分（rubric: v0）

| 维度 | 分 | 理由 |
|---|---|---|
| ER (情感共鸣)     | 4 | "如果世界是个草台班子呢"唤起具体记忆 |
| HP (钩子强度)     | 2 | 标题平铺直叙，划过时不知道点进来能获得什么 |
| QL (可传播密度)   | 4 | "学历只是敲门砖，但砖头敲不了几年"可独立截图 |
| NA (翻页动力)     | 3 | 15 张卡片有时间线推进但中间有几张可跳过 |
| AB (受众广度)     | 4 | 文科转码+迷茫 → 大众共鸣 |
| SR (社会共振)     | 4 | 蹭到"奥德赛时期"热梗 + 学历通胀的时代背景 |
| SAT (语调深度)    | 2 | 真诚叙述为主，"草台班子"有一点自嘲但不多 |

公式：(4+2+4+3+4+4+2) / 7 × 2.0 = **6.57**

📍 参考：对标「张咋啦」高表现样本 composite 7.4+

⚠️ 诊断：
- HP=2 是最大短板 → 建议重写标题，用反直觉断言或具体承诺
- NA=3 对 15 张卡片来说偏低 → 考虑砍掉中间弱页或加翻页钩子
- 整体 6.57 在 v0 rubric 下属于"中等偏上"，大概率落在基础盘~命中区间

下一步：
- 改稿后可以再打一次
- 如果已定稿准备发布 → 说"启动预测"进入 blind-predict
```

## 关键规则

1. **整数分**——不允许 4.5、3.7。强制二选一训练你的判断精度
2. **理由是诊断工具**——每个维度的理由不是装饰，复盘时用来找出"哪个维度判断错了"
3. **不写文件**——这是 draft-score 与 blind-predict 的核心区别。score 是探索，predict 是承诺
4. **可以反复打**——同一篇稿子改了再打、换个版本再打，没有副作用
5. **不预测 bucket**——"这条会有多少互动"是 blind-predict 的活。score 只输出维度分+诊断

## 不做的事

- ❌ 写任何文件
- ❌ 给 bucket 概率分布
- ❌ 触发"已发布"或"复盘"逻辑
- ❌ 建议 rubric 升级（即使打分时发现明显问题也只在输出里提示）

## 与其他 skill 的关系

- **上游**：social-media-topic-creator 出选题 → 用户写稿 → draft-score 体检
- **下游**：确定最终稿后 → blind-predict 正式预测
- **参考**：benchmark-import 提供的锚点用于对比（"这篇 composite 跟对标的哪条接近"）
- **独立**：可以脱离整个校准循环单独用——纯粹当一个写稿检查清单
