# benchmark-import — 对标账号导入

## 这个 Skill 做什么

把对标账号的内容样本（高赞/中等/低表现各选几条）映射到 7 维度评分上，形成"锚点"——让 rubric 在你没有自己数据的时候，有一个"我知道什么水平对应什么数据"的参照系。

## 为什么需要它

你刚开始做内容，rubric 是等权 v0，composite 分数跟真实表现之间没有映射关系。但如果你能告诉系统"张咋啦那条 7864 赞的帖子，7 维度大概是什么组合"，那 rubric 就有了 anchor——后续你写稿打分时，知道"我这条跟 7864 赞那条的分数差距在哪"。

冷启动期全靠对标；当你自己的 calibration_samples ≥ 10 时，对标影响自然减弱。但 benchmark 文件**不删**，它仍是选题 brainstorm 的参考框架。

## 工作目录

从 `~/.social-media-sniffer/config.json` 读取 active workspace：`config.workspaces[config.active]`

产出写入：`<workspace>/analysis/benchmarks/<对标账号名>.md`

## 输入

| 来源 | 说明 |
|---|---|
| 浏览器插件导出的 JSON | 对标账号的笔记数据（含标题、互动数据、正文描述等） |
| 用户粘贴的文本 | 对标账号的具体帖子内容（可选） |
| 用户对每条样本的印象判断 | "这条算高/中/低表现"（基于该账号自身水平） |

## 工作流程

### Phase 1: 收集材料

两种方式（可混用）：

**方式 A（推荐）**：用户用浏览器插件抓对标账号数据导出 JSON → AI 读取 JSON 自动解析。

**方式 B**：用户手动粘贴对标帖子的内容+数据。

每个对标账号建议 5-10 条样本（至少 3 条），分布要求：
- 2-3 条该账号的**高表现**内容（相对它自己的水平是爆款）
- 2-3 条**中等表现**（该账号的基本盘）
- 1-2 条**低表现**（翻车/低于预期的）

### Phase 2: 用户标注

对每条样本，问用户：
- "这条在他的号上算什么水平？高/中/低？"
- "你觉得它好在哪 / 差在哪？"（一句话就行）

用户的主观判断是关键信号——它告诉 AI "这个人认为什么是好内容"。

### Phase 3: AI 拆解 pattern

对每条样本，用当前 rubric（`rubrics/xhs-image-text-zero.md`）做 7 维度打分：

```
样本：张咋啦「文科生才是 vibe coding 最大的受益者」—— 7676 赞
ER=4  HP=5  QL=4  NA=3  AB=4  SR=4  SAT=2
composite = 7.43
用户标注：高表现
pattern：反直觉断言标题 + 身份认同 + 时代趋势
```

然后跨样本寻找 pattern：
- 高表现样本的共同维度组合是什么？
- 低表现样本缺了什么？
- 该账号的"公式"是什么？（比如"HP 永远 4-5 + SR 3-4 + 真诚语调"）

### Phase 4: 派生锚点 + 写入

将分析结果写入 benchmark 文件：

```markdown
# Benchmark: 张咋啦

## 账号概况
- 粉丝量级：20w+
- 内容形态：视频为主，偶尔图文
- 核心人设：文科背景 × AI/独立开发 × 长期主义

## 高表现样本锚点
| 标题 | 互动 | ER | HP | QL | NA | AB | SR | SAT | composite |
|...|...|...|...|...|...|...|...|...|...|

## 中等表现样本锚点
...

## 低表现样本锚点
...

## Pattern 总结
- 他的爆款公式：[...]
- 他的天花板维度：HP（标题永远很强）
- 他的短板：[...]
- 对我的启示：[...]
```

### Phase 5: 用户确认

展示给用户 review：
- "我对这些样本的打分你觉得合理吗？"
- "pattern 总结你认同吗？"

用户可以调整个别样本的分数或 pattern 判断。确认后落盘。

## 关键规则

1. **至少 3 条样本**——少于 3 条拆不出 pattern
2. **必须有高/低对比**——全是爆款没有参考价值，必须看到"什么时候翻车"
3. **不替代真实校准**——benchmark 是起步参考，不是终极真理。你自己发了 5 条之后，real data > benchmark
4. **锚点是活的**——随着你的 rubric 升级（rubric-evolve），锚点分数会被重打。旧锚点不影响新公式
5. **对标账号不等于你**——他是大 V 你是新号，绝对数据不能直接比。锚点的价值在于"维度组合"而非"互动数字"

## 与其他 skill 的关系

- **上游**：用户用 content-extractor 提取对标数据，或直接提供 JSON
- **下游**：draft-score 打分时参考锚点做对比；blind-predict 概率分布参考锚点；trend-scout 选题时参考 pattern
- **互补**：creator-profile 记录"我是谁"，benchmark-import 记录"我想成为的参照系是什么"
