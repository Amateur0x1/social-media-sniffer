# post-retro — 发后复盘

## 这个 Skill 做什么

发布 T+3 天后，用真实数据（从浏览器插件重新抓取导出）和预测做对比：
- 实际落在哪个 bucket？
- 哪些维度的判断被验证了？哪些被推翻了？
- 评论区（如果有）透露了什么信号？
- 需要写进"观察记录"的新发现是什么？

## 为什么需要它

没有复盘，前面所有的打分和预测都是自嗨。复盘是唯一能让你的 rubric 进化的东西——它告诉你"你的判断哪里对、哪里错"，而不是让你对着数据发愁然后继续用同样的方式发内容。

## 工作目录

从 `~/.social-media-sniffer/config.json` 读取 active workspace：`config.workspaces[config.active]`

复盘追加到：`<workspace>/predictions/<日期>_<短标题>.md` 的 `## 复盘` 段

观察记录写入：`<workspace>/rubric-observations/observations.md`

## 输入

| 必填 | 来源 |
|---|---|
| 对应的预测文件 | `<workspace>/predictions/` 下的文件 |
| 真实数据 | 用户用浏览器插件重新抓取导出的 JSON，或手动粘贴数据 |
| 评论内容（可选） | 用户粘贴 top 评论，或 JSON 中的评论字段 |

## 前置条件

1. 对应内容必须已经有 blind-predict 写的预测文件
2. 距离发布至少 3 天（小红书图文的数据通常 3 天内趋于稳定）
3. 如果不到 3 天但用户坚持要复盘 → 允许，但标注 `early_retro: true`

## 工作流程

### Phase 1: 读取预测 + 抓取数据

1. 读取对应的预测文件，找到 `## 预测` 段的 bucket、概率分布、中枢、推理因素
2. 读取用户提供的真实数据（JSON 或手动输入）：
   - 赞数、藏数、评论数 → 算互动总量
   - 发布距今天数
   - 评论内容（如有）

### Phase 2: 对比分析

计算：
- **实际 bucket**：互动总量落在哪个预定义区间
- **预测偏差**：vs 中枢的百分比偏差（如"中枢 50，实际 7，偏差 -86%"）
- **bucket 命中**：预测的 headline bucket 对不对
- **概率校准**：实际结果的事前概率是多少（如"落在基础盘 5-30 区间，我当时给了 25% 概率"）

### Phase 3: 维度归因

对每个维度，判断"这个维度的打分对预测的贡献是正确的还是错误的"：

```
- ER=4 → ✅ 验证：评论里有"说得太对了""这就是我"类反馈
- HP=2 → ✅ 验证：互动低大概率因为曝光不够（标题没吸引人点进来）
- SR=4 → ❓ 存疑：蹭了奥德赛热梗但似乎没有带来预期的话题流量
- QL=4 → ❌ 高估：没有人在评论里引用金句，说明金句没有真正"出圈"
```

### Phase 4: 评论分析（如有）

如果有评论数据：
- 提取 top 评论的关键词和情绪模式
- 评论里有没有"意外人群"（你没想到的受众在看你的内容）
- 有没有"金句回响"（有人在评论里引用你的原文）
- 有没有"反向信号"（争议/质疑/误解）

### Phase 5: 提炼观察

从这次复盘中提炼 1-3 条"观察"——可以是：
- 某个维度的判断规律（"HP 低于 3 的帖子，不管其他维度多高都很难破圈"）
- 某个平台行为发现（"15 张图片的帖子完读率很低，算法不推"）
- 某个受众信号（"评论区全是已在职的人，不是学生"）

### Phase 6: 落盘

**追加**到预测文件的 `## 复盘` 段（绝不修改预测段）：

```markdown
## 复盘

**复盘时间**: 2026-07-04（发布 T+3d）
**数据来源**: 浏览器插件导出 JSON

### 实绩数据
- 赞: 4 / 藏: 3 / 评: 0
- 互动总量: 7
- 落在 **基础盘 (5-30)** 桶
- 相对预测中枢 50：**偏差 -86%**
- 该结果在预测概率分布中对应 25%（基础盘区间）

### 维度归因
- ER=4 ✅ 藏赞比 > 1 说明内容本身有收藏价值
- HP=2 ✅ 验证短板：互动绝对值低 → 曝光不足 → 标题/封面没让人点
- SR=4 ❓ 奥德赛热梗未带来预期话题流量
- NA=3 ❓ 15 张可能太长

### 评论分析
- 无评论（0 条）

### 新观察
1. HP ≤ 2 时，其他维度分数再高也无法补救曝光不足的问题
2. 15 张卡片对新号来说可能太长——考虑 5-8 张更适合冷启动
3. 「奥德赛时期」热梗的搜索流量可能已过峰值

### 下次建议
- 标题必须含有明确的 value proposition 或反直觉断言
- 冷启动期控制在 5-8 张卡片
- 蹭热梗需要确认热度处于上升期而非尾声
```

同时将提炼的观察写入 `<workspace>/rubric-observations/observations.md`（累积）。

## 关键规则

1. **绝不修改预测段**——只往 `## 复盘` 段追加
2. **T+3 天是默认窗口**——小红书图文 3 天后数据基本稳定。用户坚持早复盘可以，但标注
3. **维度归因必须具体**——不能写"预测偏了"就完事，必须指出哪个维度判断错了、为什么
4. **观察是 rubric 升级的种子**——每次复盘提炼的观察，积累到一定量后触发 rubric-evolve
5. **数据来源要标注**——手动粘贴 vs 插件 JSON，方便核查

## 触发 rubric-evolve 的信号

当以下情况出现时，提示用户考虑跑 rubric-evolve：
- 连续 ≥ 3 次预测同向偏差（一直高估或一直低估）
- 某个维度连续 3 次被归因为"判断错误"
- 累积 ≥ 5 条观察记录中有 ≥ 3 条指向同一个方向

## 与其他 skill 的关系

- **上游**：blind-predict 的预测文件是 retro 的输入
- **下游**：观察累积后 → rubric-evolve 升级公式；评论数据累积后 → audience-lens 更新受众画像
- **数据来源**：浏览器插件（social-media-sniffer extension）导出的 JSON
- **回馈**：复盘结论影响下一次选题（topic-creator）和打分（draft-score）
