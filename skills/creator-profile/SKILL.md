# 账号画像（自定义面 + 数据面）

## 这个 Skill 做什么

维护当前 workspace（= 当前账号）的完整画像，包含两个维度：

| 维度 | 名称 | 来源 | 回答的问题 |
|------|------|------|-----------|
| 自定义面 | Creator Profile | 用户自述 + 发布数据 | "我是谁、我想做什么、我面向谁" |
| 数据面 | Audience Lens | 复盘评论聚类 + 互动行为 | "谁真的在看我、他们为什么来" |

**两个面共存，不替代。**

- 冷启动时只有自定义面（用户自述）
- 有了 ≥ 3 篇有评论的复盘后，可以产出数据面
- 两者之间的差异不是"错了"，是**战略信号**——"你想吸引 A，但数据说 B 在看你"

## 工作目录

从 `~/.social-media-sniffer/config.json` 读取 active workspace：`config.workspaces[config.active]`

```
<workspace>/
├── profiles/
│   └── <账号名>.md              # 自定义面（本 skill 维护）
└── audience/
    └── audience.md              # 数据面（本 skill 维护）
```

## 第一部分：自定义面（Creator Profile）

### 什么时候做

冷启动就能做——不需要任何数据，纯对话建立。

### 画像文档格式

```markdown
# [账号名] 画像

## 最后更新
<日期>

## 基本信息
- 账号名：
- 平台：（小红书/抖音/公众号/多平台）
- 关联产品：（如果有）
- 一句话定位：

## 产品信息（如有关联产品）
- 产品名：
- 做什么的：
- 核心功能/卖点（最多3个）：
- 和竞品的核心差异：

## 目标用户（你设定的）
- 主要人群：
- 他们的痛点：
- 他们活跃的场景/平台：
- 用户画像关键词：

## 内容策略
- 账号阶段：（刚起步 / 有基础 / 转型中）
- 内容人设：（以什么身份说话）
- 调性关键词：（3-5个词概括风格）
- 内容形式：（图文为主 / 视频为主 / 混合）
- 发布频率：

## 能力边界
- 能拍视频吗：
- 能做设计/P图吗：
- 每周能投入多少时间：
- 有没有预算：
- 其他限制或优势：

## 已有内容表现
- 已发布数量：
- 表现最好的内容（标题+数据）：
- 表现差的内容：
- 内容风格总结：
- 当前问题/改进方向：

## 竞品参考
- 参考的竞品/对标账号：
- 从对标学到的关键策略：

## 备注
（其他补充信息）
```

### 建立流程

通过对话收集信息，分步骤问，每次 1-2 个问题：

**第一轮：这个号是做什么的**
- 账号名？平台？
- 推产品还是做个人IP？
- 如果有产品——产品叫什么，核心卖点？

**第二轮：面向谁**
- 想触达什么人？
- 他们有什么痛点？

**第三轮：怎么做内容**
- 用什么人设/身份发内容？
- 希望什么调性？
- 图文还是视频？

**第四轮：能力边界**
- 每周能投入多少时间？
- 有什么限制？

**第五轮：已有内容**
- 发过内容吗？有数据可以分析吗？

### 更新流程

用户说"更新画像""加点信息"时：
1. 读当前画像
2. 根据新信息更新对应部分
3. 更新"最后更新"日期

## 第二部分：数据面（Audience Lens）

### 什么时候做

需要复盘数据积累——评论是主要数据源。

| 情况 | 行为 |
|------|------|
| 0 篇复盘 + 无 benchmark | 告诉用户"数据面需要复盘数据，先发几篇跑完复盘再来" |
| 0 篇复盘 + 有 benchmark | 生成"未验证种子画像"，全文标"基于对标推测" |
| 1-2 篇有评论的复盘 | 可产出但置信度低，特征多标"假设" |
| ≥ 3 篇有评论的复盘 | 正常产出，可做验证性结论 |

### 数据来源

| 来源 | 信号类型 |
|------|---------|
| 复盘段的 top 评论 | **主数据源**——评论文本 + 赞数 |
| 互动数据比率 | 薄信号——藏赞比高="实用型受众"，评赞比高="讨论型受众" |
| benchmark 评论（如有） | 冷启动 seed |

### 工作流程

#### Phase 1: 收集数据

扫描 `<workspace>/predictions/` 下所有预测文件的 `## 复盘` 段：
- 提取 top 评论内容和赞数
- 提取互动数据
- 统计有评论的复盘篇数

#### Phase 2: 评论聚类

按四个维度分析：

**1. 自我认同**——"我也是…"/"作为一个…"模式
- 什么身份标签反复出现？
- 例："大厂打工人""同文科转码""一人公司想做但没勇气"

**2. 情绪寄存**——他们来评论是为了什么情绪？
- 被验证（"说得太对了"）
- 宣泄（"我也好累"）
- 求助（"那该怎么办"）
- 抬杠（"我不同意"）
- 占比分布

**3. 反驳点**——哪些观点引来稳定反对
- 这是你的"边界"——反复被反对的点 = 你在推某些人的按钮
- 边界可以是好事（有争议 = 有立场 = 有人设）

**4. 语言风格**——他们怎么说话
- 玩梗密度、真诚 vs 戏谑
- 有没有复制你的金句 / 创造新梗

#### Phase 3: 交叉检验（自定义面 × 数据面）

这是本 skill 最有价值的一步——把数据面的发现跟自定义面做对比：

```
自定义面说："我的目标受众是想转码的文科生"
数据面发现："实际评论者 80% 是已在职的大厂人，想做副业/独立开发"

→ Gap signal: 你吸引的不是"还没转码的人"，而是"已经转完了想更进一步的人"
```

这种 gap 不是"错了"——它是战略信息。用户可以：
- 调整方向适配真实受众
- 调整内容去吸引目标受众
- 接受现实，重新定义目标受众

#### Phase 4: 写入

产出写入 `<workspace>/audience/audience.md`：

```markdown
# <账号名> — 受众画像（数据面）

**版本**: v1
**置信度**: 🟢 数据扎实（基于 5 篇有评论的复盘）
**数据基础**: 5 篇复盘 / 47 条评论
**上次更新**: 2026-07-10

## 验证特征（有数据支撑）
- [特征] + 证据条数 + 出处

## 假设特征（待验证）
- [特征] + 为什么猜测 + 需要什么验证

## 反画像（不是你的受众）
- [描述] + 为什么排除

## 情绪地图
- 来找什么情绪的分布

## 语言特征
- 他们怎么说话

## 自定义面 × 数据面 交叉检验
- Gap 1: 自定义面说...，数据面显示...
- Gap 2: ...
- 对内容策略的启示：...

---
版本历史：
- v1 — 基于 5 篇复盘 / 47 条评论，主要发现：...
```

## 触发逻辑

| 用户说 | 执行哪个部分 |
|--------|-------------|
| "建画像""我要开始做内容""新账号" | 自定义面（建立/更新） |
| "更新画像""改一下信息" | 自定义面（更新） |
| "我的观众是谁""分析评论""刷新受众" | 数据面（建立/更新） |
| "看画像""看看我的画像" | 展示两个面的摘要 + gap |

当用户说"看画像"时，AI 应该同时展示两个面的核心信息，并把交叉检验的 gap 突出显示——这是最有行动价值的信息。

## 关键规则

1. **自定义面通过对话建立**——分步骤问，每次 1-2 个问题，不像填表
2. **数据面从评论聚类派生**——不手写。用户想手动加 → 允许但标"user-asserted"
3. **验证特征需 ≥ 3 条评论证据**——不够的降到"假设特征"
4. **两面共存不替代**——自定义面是"设定"，数据面是"现实"
5. **交叉检验诚实**——gap 如实标出，不强行编一个和谐故事
6. **数据面覆盖式重建**——每次执行重写 audience.md 全文，版本历史 append 一行
7. **局限性诚实**——评论 ≠ 全部受众（沉默大多数不在数据里）

## 与其他 skill 的关系

- **下游**：topic-creator 读两面——自定义面决定方向，数据面决定"受众在不在乎"
- **下游**：trend-scout 过滤热点时参考数据面
- **联动**：rubric-evolve 参考数据面调整维度权重（"受众不在乎 NA → 可以降权"）
- **上游**：post-retro 积累评论数据 → 触发数据面更新
- **上游**：benchmark-import 提供冷启动 seed

## 交互风格

- 对话式，不要像填表
- 如果用户答得模糊，追问具体细节
- 分析评论时用客观语气，gap 不带判断（"你的设定是 A，数据显示 B"而不是"你错了"）
- 建议每 3-5 篇新复盘后刷新一次数据面
