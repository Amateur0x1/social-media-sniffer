# 内容创作者画像建立与维护

## 这个 Skill 做什么

为用户的**每一个内容账号**维护一份独立的画像文档，记录该账号的产品定位、目标人群、内容风格、能力边界、已有内容表现。

一个用户可能同时运营多个完全不同的账号（比如一个推广自己的 App，一个做个人 IP，一个帮公司运营），每个账号的需求、人设、受众都不同，所以**必须分开管理，不能混在一起**。

## 工作目录

所有文件存放在用户通过 `init` Skill 配置的工作目录下。路径从配置文件读取：

```
~/.social-media-sniffer/config.json → "workspace" 字段
```

跨平台：macOS/Linux 为 `~/.social-media-sniffer/config.json`，Windows 为 `%USERPROFILE%\.social-media-sniffer\config.json`。

**启动时必须先读取 config.json 获取 workspace 路径。如果配置不存在，提示用户先完成初始化（参考项目根目录 agent.md）。**

## 文件结构

```
<workspace>/
├── profiles/                          # 所有账号画像
│   ├── _index.md                      # 账号索引（列出所有账号及简介）
│   ├── 煮理人.md                       # 账号1的画像
│   ├── 个人技术号.md                    # 账号2的画像
│   └── xxx公司官方号.md                 # 账号3的画像
├── data/
├── analysis/
└── topics/
```

**关键设计**：
- 每个账号一个 `.md` 文件，文件名就是账号名/产品名（用户自己取）
- `_index.md` 是索引文件，快速查看所有账号及当前状态
- 其他 Skill 使用时，需要先确认「当前在为哪个账号工作」

## 索引文件格式（_index.md）

```markdown
# 我的内容账号

## 账号列表

| 账号名 | 平台 | 产品/方向 | 阶段 | 最后更新 |
|--------|------|-----------|------|----------|
| 煮理人 | 小红书 | 菜谱管理App | 刚起步 | 2026-06-30 |
| ... | ... | ... | ... | ... |
```

## 单个账号画像文档格式

```markdown
# [账号名] 画像

## 最后更新
<日期>

## 基本信息
- 账号名：
- 平台：（小红书/抖音/公众号/多平台）
- 关联产品：（如果是推产品的话）
- 一句话定位：

## 产品信息（如果有关联产品）
- 产品名：
- 做什么的：
- 核心功能/卖点（最多3个）：
- 和竞品的核心差异：

## 目标用户
- 主要人群：
- 他们的痛点：
- 他们活跃的场景/平台：
- 用户画像关键词：

## 内容策略
- 账号阶段：（刚起步 / 有基础 / 转型中）
- 内容人设：（以什么身份说话）
- 调性关键词：（3-5个词概括风格）
- 内容形式：（图文为主 / 视频为主 / 混合）
- 发布频率：

## 能力边界
- 能拍视频吗：
- 能做设计/P图吗：
- 每周能投入多少时间在这个号上：
- 有没有预算（投流/找人拍等）：
- 其他限制或优势：

## 已有内容分析
- 已发布数量：
- 表现最好的内容（标题+数据）：
- 表现差的内容：
- 内容风格总结：
- 当前问题/改进方向：

## 竞品参考
- 参考的竞品账号：
- 从竞品学到的关键策略：

## 备注
（其他补充信息）
```

## 工作流程

### 场景一：首次使用（没有 profiles/ 目录）

1. 创建 `<workspace>/profiles/` 目录
2. 告诉用户这个工具支持多账号管理
3. 问：「你现在想先建哪个账号的画像？你一共在运营几个号？」
4. 进入单个账号的画像建立流程

### 场景二：新建一个账号画像

通过对话收集信息，分步骤问，每次 1-2 个问题：

**第一轮：这个号是做什么的**
- 这个账号叫什么？（或者你想怎么称呼它）
- 在哪个平台？
- 是推产品的还是做个人IP？还是帮公司运营的？
- 如果有产品——产品叫什么，核心卖点是什么？

**第二轮：这个号面向谁**
- 这个号想触达什么人？
- 这些人有什么痛点是你能解决的？

**第三轮：这个号怎么做内容**
- 你想用什么人设/身份来发内容？
- 你希望内容是什么调性？（专业严肃？轻松有趣？真实分享？）
- 计划以图文为主还是视频为主？

**第四轮：这个号的能力边界**
- 你在这个号上每周能投入多少时间？
- 能力上有什么限制？（不会拍视频、不会P图等）

**第五轮：这个号发过内容吗**
- 如果发过，引导用户提供数据：
  - "你可以用 sniffer 浏览器扩展抓一下你这个号已发布的内容，导出 JSON 给我"
  - "我会分析你的内容风格和数据表现，写进画像里"
- 如果没发过，标记为「尚未发布内容」，后续有了再更新

收集完毕后：
1. 写入 `<workspace>/profiles/<账号名>.md`
2. 更新 `_index.md` 索引
3. 给用户看一遍确认

### 场景三：更新某个账号画像

1. 先确认要更新哪个账号（如果有多个）
2. 读取该账号的画像文件
3. 根据新信息更新对应部分
4. 更新「最后更新」日期
5. 告知用户具体改了什么

### 场景四：切换/选择当前工作账号

当用户在使用其他 Skill（选题、分析）时，如果有多个账号，需要先确认「你现在在为哪个号工作？」

流程：
1. 读取 `_index.md`，列出所有账号
2. 让用户选择
3. 后续的选题/分析都基于所选账号的画像来做

### 场景五：被其他 Skill 调用

当 `social-media-topic-creator` 或 `content-extractor` 需要了解用户信息时：

1. 检查 `<workspace>/profiles/` 是否存在
2. 如果不存在 → 引导用户先建立画像
3. 如果存在，检查有几个账号：
   - 只有一个 → 直接读取使用
   - 有多个 → 问用户「你现在是在为哪个号做？」然后读取对应画像

### 场景六：分析用户已发布内容

当用户提供了自己某个账号的发布数据（JSON）时：

1. 确认这个数据属于哪个账号
2. 用 `content-extractor` 的能力进行分析（视频截帧+转写、图片下载）
3. 将分析结论（风格总结、数据表现、问题和改进方向）写入该账号画像的「已有内容分析」部分
4. 分析产出（截帧、图片等）存放在 `<workspace>/analysis/<日期>-<账号名>/`

## 交互风格

- 对话式，不要像填表。一次问 1-2 个问题。
- 如果用户答得模糊，追问具体细节（「你说目标用户是年轻人，能再具体一点吗？是大学生？独居打工人？宝妈？」）
- 对于「能力边界」部分要诚实友善地问，不要让用户觉得在被审判
- 如果用户不确定某些问题（比如"我还没想好人设"），可以给建议但标记为"待确认"
- 分析用户已有内容时，用鼓励的口吻指出问题，不要打击积极性
- 当用户有多个号时，每次对话开始要明确「今天在为哪个号工作」，避免信息串了

## 注意事项

- 每个账号的画像是独立的，不同账号之间的策略、人设、调性可能完全不同，绝对不能混淆
- 画像文件是用户的核心资产，修改时要谨慎，不要丢失已有信息
- 每次更新都保留「最后更新」时间戳
- 文件名用账号名/产品名，保持直观易找
- 文档内容是给 AI 读的，格式要结构化、明确，不要写散文
- 如果用户说「我有个新号要做」，直接进入新建流程，不要去改已有账号的画像
