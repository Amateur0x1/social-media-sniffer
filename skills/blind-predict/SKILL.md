# blind-predict — 盲预测

## 这个 Skill 做什么

给你确定要发布的最终稿写一份**不可修改的盲预测日志**。预测段一旦落盘，只能往后面追加复盘段，绝不能回头改预测——这是逼你诚实面对自己判断的机制。

## 核心原则：盲预测（Blind Prediction）

预测必须在看到任何实际数据**之前**写完。如果你已经发了、已经看到了赞藏数据，就不能再"预测"了——那叫马后炮，不叫校准。

## 工作目录

从 `~/.social-media-sniffer/config.json` 读取 active workspace：`config.workspaces[config.active]`

预测文件写入：`<workspace>/predictions/<日期>_<短标题>.md`

## 输入

| 必填 | 来源 |
|---|---|
| 最终稿内容 | 用户提供（文本/文件路径） |
| rubric | `rubrics/` 下当前版本 |
| benchmark 锚点（如有） | `<workspace>/analysis/benchmarks/` |
| 历史预测（如有） | `<workspace>/predictions/` 下已有文件 |

## 工作流程

### Phase 1: Blind check 自检

确认：
- 用户没有在对话中提到这篇帖子的任何实际数据
- 这篇内容还没有发布
- 没有人告诉 AI 这篇发了之后表现如何

任何一条触犯 → **拒绝执行**。告诉用户："你已经看到数据了，不能做盲预测。请用 post-retro 做复盘。"

### Phase 2: 7 维打分

同 draft-score 的打分逻辑，逐维度 0-5 + 理由。

### Phase 3: 锚点对比

找 2-4 个 composite 接近的样本（来自 benchmark 或已有预测历史），列出对比：

```markdown
## 锚点对比

| 对照样本 | composite | 实绩 | 异同 |
|---|---|---|---|
| 张咋啦「文科生才是 vibe coding 最大受益者」| 7.43 | 7676 赞 | HP 更强、AB 更广 |
| 我的「文科转码经验分享」| ~7.0 | 223 赞 | 相似主题但新号 vs 大 V |
```

如果校准样本不够（< 2 个邻近样本），明确写"锚点 N/A——校准池不足"。**不删段，不省略**。

### Phase 4: Bucket + 概率分布

给出这篇发布后**互动总量（赞+藏+评）大概率落在哪个区间**：

```markdown
## 预测

**Bucket**: 命中（30-100 互动）

**概率分布**:
- 底部 (< 5) → 5%
- 基础盘 (5-30) → 25%
- **命中 (30-100) → 45%**（中枢 ~50 互动）
- 小爆 (100-500) → 20%
- 大爆 (> 500) → 5%

**一句话 reason**:
> ER=4 + SR=4 话题有共鸣，但 HP=2 标题太弱限制了首次曝光转化率；新号基础盘有限，大爆需要标题先过关。
```

**概率分布加起来必须 = 100%**——这是逼你诚实的工具。

### Phase 5: 反事实场景

每个可能的 bucket 写一段"如果落在这里，意味着什么"：

```markdown
## 反事实场景

**如果大爆 (> 500)**:
- 说明 SR（奥德赛时期热梗）的流量加持超出预期
- HP 短板被话题红利弥补了

**如果命中 (30-100)**:
- 基准线验证：话题对了但呈现方式还有优化空间

**如果底部/基础盘 (< 30)**:
- HP 短板被证实是致命的——好内容也会因为烂标题被埋没
- 可能：15 张图太长，完读率极低导致算法不推
```

### Phase 6: 落盘

将完整预测写入文件：`<workspace>/predictions/<日期>_<短标题>.md`

文件结构：
```
# <标题> — 预测日志

**预测时间**: YYYY-MM-DD
**Rubric Version**: v0
**校准样本数**: N
**Confidence**: 🔴极低 / 🟡偏低 / 🟢正常 / 🔵稳健

## 输入快照
（7 维分数 + composite）

## 预测                    ← 这一段不可修改
（bucket + 概率 + 中枢 + reason）

## 推理因素
（每个关键判断 + 方向 + 置信度）

## 锚点对比

## 反事实场景

---
（以下留给 post-retro 追加）

## 复盘
（待填）
```

## 关键规则

1. **预测段不可修改**——写完就锁。觉得写错了？写新文件，旧的保留（错误本身是数据）
2. **概率分布 = 100%**——逼你诚实分配信心
3. **blind 是硬约束**——看到过数据就不能预测。没有例外
4. **confidence 要诚实**——校准样本 < 5 时标🔴/🟡，不装自信
5. **锚点段必须有**——不够就写 N/A，不要删段

## 不做的事

- ❌ 给已发布的内容补预测（那叫马后炮）
- ❌ 修改已写的预测段（只能追加复盘）
- ❌ 跳过概率分布只给 bucket（分布是诚实度测试）

## 与其他 skill 的关系

- **上游**：draft-score 体检确认 OK → blind-predict 正式预测
- **下游**：发布后 → post-retro 回收数据对比预测
- **参考**：benchmark-import 的锚点用于 Phase 3 对比
- **互动**：rubric-evolve 升级公式后，会标注"该预测基于 v0/v1/v2 公式"
